# 0010: 同一鎖定循環內的抽題規則 — 第1次隨機、第2次扣除後抽、第3次重新隨機

## 狀態
已接受

## 背景
承舊系統既有的重考規則（每輪最多連續 3 次機會，3 次都沒過鎖定 7 天，見舊 repo `exam_logic.py`）。題庫目前每階段皆有 50 題以上（見與使用者的討論，確認題庫量已足夠，不存在抽題數量不足的問題，見 [0007](./0007-edge-function-for-grading.md) 的修訂）。

舊系統每次都是對整個題庫完全隨機抽 25 題（`random.sample`），三次機會之間可能重複、也可能不重複，沒有刻意設計。使用者希望在同一輪 3 次機會內，抽題有更明確的規則，讓學員在合理次數內盡量涵蓋到不同題目，而非單純看運氣。

## 決策
在同一輪最多 3 次的鎖定循環內：

1. **第 1 次**：從該考試科目（該語言）的全部題庫中隨機抽 25 題
2. **第 2 次**：從「全題庫扣除第 1 次抽過的題目」剩餘的題目中抽 25 題
   - 題庫剛好 50 題時，剩餘的就正好是另外 25 題，直接全部出題，不需要再抽
   - 題庫超過 50 題時，從扣除後剩餘的題目中隨機抽 25 題
3. **第 3 次**：不考慮前兩次抽過什麼題目，重新回到全題庫隨機抽 25 題（等同重新開始一輪的抽法）
4. 進入鎖定期後解鎖、開始新一輪的 3 次機會時，抽題規則同樣從「第 1 次」的邏輯重新開始
5. **抽出的 25 題，顯示給學員作答時的題目順序需重新隨機排列**，不得依照題庫原始建置順序（如題目 ID 或建立時間順序）呈現——避免同一份題庫、同一批抽出的題目，每次都以同樣的順序出現而被學員記住「第幾題通常是哪一類」；選項順序沿用舊系統既有的洗牌邏輯（`option_order`），兩者是分開獨立的隨機化，缺一不可

此規則只套用在**同一輪鎖定循環內的次數計算**，與 [0006](./0006-pass-requires-manager-confirmation.md) 的「存疑保留最終不合格不追溯扣考試機會、直接重新計算」的邏輯搭配時，被判定作廢、發回重考的那一次不算在這個 1/2/3 次序裡（因為它原本是通過的，額度未被扣，重考視為新的第 1 次）。

## 後果
- 需要在出題邏輯（[Edge Function](./0007-edge-function-for-grading.md)）裡額外記住「這一輪目前是第幾次」以及「上一次抽過哪些題目 ID」，比單純的 `random.sample` 多一點狀態追蹤
- 每階段題庫需要維持在 50 題以上才能讓第 2 次「扣除後抽 25 題」有題可抽；若某語言題庫掉到 50 題以下（理論上不應該發生，但若發生），第 2 次會抽不滿 25 題——**目前不特別處理這個邊界情況，因為已確認題庫皆有 50 題以上**
