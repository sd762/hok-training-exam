# 0009: 機構清單改為後台可維護資料，不再寫死在程式碼

## 狀態
已接受

## 背景
舊系統的機構結構（機構類別：護理之家／法人館／養護機構，及其底下的機構名稱清單，如法人館底下的 1館/2館/3館、養護機構底下的清福/清氣/清心…等 14 個機構）寫死在 `models.py` 的 `INSTITUTION_STRUCTURE` 常數裡。新增機構、機構改名、機構停用都得改程式碼、重新部署才能生效。

## 決策
機構清單改為一張後台可維護的資料表（機構類別 + 機構名稱，兩層結構），在「系統設定」或對應管理頁面裡就能新增/編輯/停用機構，不需要改程式碼或重新部署。學員資料表（`institution_category`/`institution_name`）與機構管理者資料表改用外鍵參照這張機構表，而非自由文字或程式碼常數。

## 後果
- 機構異動（展店、改名、裁撤）由管理者自行在後台操作即可生效，不需要等開發或部署
- 需要多做一個機構管理的 CRUD 介面（新增/編輯/停用機構類別與機構名稱），比直接寫死常數多一點開發工作量
- 既有學員/機構管理者資料若指向被停用的機構，介面上需要決定顯示方式（例如標示「已停用」而非直接消失，避免歷史紀錄顯示異常）——**細節留待實作階段設計**
