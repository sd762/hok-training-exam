# 0006: 及格作答需平台管理者核對後才正式生效

## 狀態
已接受（2026-07-25 修正審核者：由「機構管理者」改為「平台管理者」，見下方修正說明）

## 背景
承 [0005](./0005-webcam-proctoring-soft-flag.md) 的鏡頭監考機制，需要明確定義「誰在什麼時候看監考證據、看了之後系統狀態怎麼變化」，否則監考快照存了也沒人看、沒有明確的後續流程。

> **修正說明（2026-07-25）**：本 ADR 原始版本寫審核者是「機構管理者」，經使用者釐清角色權限（見 [0013](./0013-five-tier-role-hierarchy.md)）後修正——機構管理者只能**查看**自己機構的考測結果與分析，**沒有**審查合格與否的權限；審查權限屬於**平台管理者**。以下內容已更新為正確版本。

## 決策
只有**及格**的作答需要人工核對，不及格的作答不需要審查（反正學員會再重考，審查沒有意義）。

流程：
1. 學員完成作答並自動評分。**若不及格**：維持現行邏輯（見 [exam_logic.py 摘錄]），直接計入重考次數/鎖定判斷，無需管理者介入。
2. **若及格**：作答狀態進入「待核對」（`pending_review`），系統通知**平台管理者**（角色定義見 [0013](./0013-five-tier-role-hierarchy.md)）。機構管理者雖然看得到這筆「待核對」狀態出現在自己機構的考測結果列表中，但沒有操作審核的按鈕/權限。
3. 平台管理者查看該次作答的監考證據（快照、疑似違規事件紀錄），核對作答者身分是否無誤：
   - **核對無誤** → 狀態改為「已確認通過」（`confirmed_passed`），正式納入及格紀錄；對應的監考快照可以刪除（呼應儲存空間管理）
   - **有出入** → 狀態改為「存疑保留」（`flagged`），監考快照與紀錄保留不刪，待進一步人工調查後才決定最終是否維持及格或視為不合格需重測

## 後果
- 每位學員一輪最多 3 次考試機會，及格才需要審查，審查工作集中在平台管理者身上（而非分散在各機構管理者），需確保平台管理者人數/量能足以應付全機構的審查需求（不像原本設想的機構管理者分攤模式）
- 系統需要新增「待核對／已確認／存疑保留」三態的狀態欄位，而非單純的及格/不及格二元判定
- **階段推進本身綁定「目前階段已確認通過」**（使用者已於 2026-07-24 確認）：學員只有在目前受訓階段的作答狀態為「已確認通過」時，才視為完成該階段、可以推進到下一階段。只要還處於「待核對」或「存疑保留」，就不算完成目前階段——自然不會進入下一階段，也就不會誤觸發下一階段的到期通知。三個里程碑（滿1個月/滿3個月/滿1年）原則上時間點不會重疊，只有「目前階段一直卡在待核對/存疑保留、拖到下個里程碑時間點」這種邊界情況才需要這條規則來擋下誤發通知。
- 「存疑保留」最終被判定為不合格時，**不追溯扣掉考試機會**——因為審查必然發生在作答當下之後（有時間落差，不是即時判定），這次作答在送出當下已經是「合格」狀態，之後才被推翻，視為這次作廢，直接重新計算，發回重考；不計入原本 3 次鎖定循環的額度（使用者已於 2026-07-24 確認）
