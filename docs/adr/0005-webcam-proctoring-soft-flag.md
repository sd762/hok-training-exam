# 0005: 測驗鏡頭監考 — 前端人臉偵測 + 軟性標記，不自動硬扣分

## 狀態
已接受

## 背景
使用者提出考測期間要求開啟鏡頭（含手機前鏡頭），全程無預警擷取畫面以確認作答者為本人；若人臉連續 3 秒未出現在畫面中，原始構想是**立即中止考試並扣掉一次考試機會**。

系統本來就是純前端直連 Supabase 的架構（見 [0001](./0001-github-pages-supabase-over-flask-render.md)），沒有伺服器可以做即時影像運算，因此人臉偵測只能在瀏覽器端執行。可行方案是用瀏覽器內建的人臉偵測模型（如 MediaPipe Face Detection，WASM 執行，純前端、免費、不需後端算力），配合 `getUserMedia({facingMode:"user"})` 取得鏡頭畫面（手機前鏡頭亦支援）。

但「連續 3 秒沒偵測到臉就自動扣一次機會」有誤判風險：光線不足、低頭寫字、口罩/眼鏡反光都可能讓偵測暫時抓不到臉，對本人造成不公平的誤殺。

## 決策
1. 監考期間持續在前端執行人臉偵測，並依隨機/固定間隔擷取畫面快照，上傳至 Supabase Storage，與該次 `Attempt` 綁定，作為稽核佐證。
2. 人臉連續 3 秒未偵測到時，**不自動中止考試、不自動扣考試機會**。改為：
   - 在畫面上顯示提醒，要求作答者回到鏡頭畫面內（考試繼續進行，不中斷作答）
   - 記錄一筆「疑似違規事件」（時間戳記 + 當下快照），與該次 `Attempt` 一併保存
3. 作答結束後，管理者在「作答明細」頁面可以看到該次作答是否有疑似違規事件與對應快照，由管理者**人工判斷**是否要作廢該次成績、要求重測（是否計入 3 次額度上限由管理者操作決定，而非系統自動扣）。
4. 開始監考鏡頭前，需先顯示**同意書畫面**，明確告知作答者鏡頭會全程錄製、無預警擷取畫面，需明確同意才能開始測驗——這涉及外籍移工的臉部生物特徵資料，屬於需要明確告知並取得同意的個資類別。

## 後果
- 換得公平性：避免光線、姿勢等環境因素造成的誤判直接懲罰無辜的作答者
- 管理者多了一項人工複核的工作量（需要進去看疑似違規紀錄、決定是否作廢重測）
- 需要額外的 Supabase Storage 額度存放監考快照（免費方案 1GB，快照數量多時需留意用量與定期清理策略——**保留期限與清理規則待後續確認**）
- 需要在學員端流程新增「鏡頭權限 + 同意書」步驟，若學員拒絕授權鏡頭則無法開始測驗（需設計對應提示文案，含多語言版本）
