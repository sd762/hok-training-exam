# 0015: 題庫改為三語言完全獨立，取消「一題多語言」共用機制

## 狀態
已接受（推翻先前的多語言設計，見下方背景）

## 背景
專案最初調查舊系統前身 OnlineExamMaker 時，認定的核心痛點之一是：「9 個測驗科目其實是 3 個受訓階段 × 3 個語系的組合...同一題要在三個地方各建一次，改一題要改三份」。當時據此設計「一題多語言」機制（`QuestionBank` + `QuestionTranslation`，共用同一份正確答案位置），並在工單 06 實作為 `question_bank` + `question_translation` 兩張表、繁體中文選項順序鎖定答案位置、越南文/印尼文只是翻譯文字。

在實際釐清匯入流程時，使用者明確表示：中文題庫、印尼題庫、越南語題庫**彼此間完全獨立、沒有任何對應關係**——不是同一題目的三語言翻譯，而是三份各自獨立存在、各自建置與維護的完整題庫。三語言的題目內容、題數、題目順序都可能完全不同（例如中文50題、印尼55題、越南60題，彼此無關聯）。

使用者額外指出的理由：**跨語言連動的代價太大，一個環節沒弄好，會牽連全部語言一起出錯**。共用同一份正解位置意味著中文題目的選項順序、數量一旦調整不慎，會直接影響到已經翻譯好的越南文/印尼文版本是否還能正確對應；三語言完全獨立雖然多了維護成本，但每個語言的題庫是各自獨立的風險範圍，一個語言的操作失誤不會波及其他語言。

## 決策
取消「一題多語言」的共用機制：
1. **刪除 `question_translation` 表**，`question_bank` 表新增 `lang_code` 欄位，每一列就是一個語言、一題完整內容（題目、選項、正確答案位置、解析）
2. 三個語言的題庫在管理介面、匯入邏輯上都是**完全獨立**的操作對象——沒有「翻譯範本」「依序對應既有題目」這類跨語言關聯機制
3. Excel 匯入時，中文/越南文/印尼文都走同一套「建立新題目」流程，差別只在 `lang_code` 參數，不再有「非中文匯入只能補翻譯、不能建立新題目」的限制

## 後果
- **走回舊系統前身 OnlineExamMaker 被認定的缺點模式**：以後同一個知識點要讓三個語言都涵蓋到，得三語言各自建一次、各自維護；改一題的內容，不會連動更新其他語言版本，需要在三個地方分別修改。這是使用者已明確確認並接受的代價，不是遺漏。
- 換得的彈性：三語言的題目數量、內容、涵蓋範圍可以完全按各語言實際需求（如舊系統前身痛點分析後的認知：外語學員學習門檻高，題庫規模不需要跟中文對等）獨立調整，不受「必須先有對應中文題目才能匯入翻譯」的順序限制
- Schema 大幅簡化：不再需要「答案位置鎖定在中文選項順序、其他語言只存翻譯文字」這套跨語言換算機制（原本呼應 ADR 0007 的正解保護設計，改成每語言各自存放完整的 `answer_json`，保護機制本身不變——正解依然只有 Edge Function 能讀到，只是不再與其他語言共用同一份位置資料）
- 工單 06 已完成的 `question_translation` 相關程式碼（多語言分頁表單、翻譯範本下載/比對匯入）需要重寫或移除
