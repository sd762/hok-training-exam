# 0011: 到期通知改為提前 3 天、每天檢查 1 次即可

## 狀態
已接受

## 背景
承 [0003](./0003-keepalive-github-actions.md) 與後續討論：到期通知檢查改用 GitHub Actions 排程呼叫 Supabase Edge Function 執行（合併保活與通知檢查於同一個排程工作）。舊系統的規則是里程碑前 7 天進入通知窗口（`NOTIFY_WINDOW_DAYS = 7`），伺服器常駐執行、每 6 小時檢查一次。

使用者調整通知提前天數為 3 天，並指出：由於同一學員同一階段只會通知一次（`NotificationLog` 去重），同一天內檢查 1 次或檢查很多次，結果完全一樣——多檢查沒有額外效果，純粹浪費呼叫次數。

## 決策
1. 通知提前天數由 7 天改為 **3 天**（里程碑前 3 天進入通知窗口）
2. GitHub Actions 排程檢查頻率改為**每天 1 次**即可，不需要沿用舊系統每 6 小時檢查一次的頻率

## 後果
- 排程呼叫次數大幅降低（一天 1 次 vs. 一天 4 次），更省 GitHub Actions 分鐘數額度與 Edge Function 呼叫次數
- 通知窗口縮短為 3 天，機構管理者收到提醒後可運用的排考準備時間比原本的 7 天少，需確保管理者看到通知後能及時安排（此為使用者已確認的決策，不在此重新討論）
- 每天固定時間執行 1 次即可，時段可選在離峰時段（例如凌晨），不影響白天的系統使用
