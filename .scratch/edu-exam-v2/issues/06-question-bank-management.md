# 06 — 題庫管理（三語言各自獨立）+ Excel 匯入

**What to build:** 平台管理者可以管理各受訓階段的題庫。**繁體中文／越南文／印尼文為三份完全獨立的題庫**（見 [ADR 0015](../../../docs/adr/0015-independent-per-language-question-banks.md)，2026-07-25 修訂——原規劃為「一題多語言」共用機制，使用者評估跨語言連動風險過高後推翻，改為互不相關的三份題庫），各語言各自管理題目內容、題數、正確答案，互不影響、互不連動。支援用 Excel 批次建立題目，三語言使用同一套範本格式，各自匯入互不相關。

**Blocked by:** 03

**Status:** ready-for-agent

- [~] 平台管理者可以針對指定受訓階段＋指定語言，手動新增一題（題型、配分、題目、選項、正確答案、解析），正確答案的位置記錄在該語言自己的選項順序上
      → UI 已完成、建置通過；待人工測試實際點擊流程
- [~] 平台管理者可以用 Excel 批次建立整批題目（三語言共用同一套範本格式：題型/分數/題目/選項/正確答案位置/解析），匯入時選定目標語言，與其他語言互不相關
      → 範本下載、解析、批次建立（逐筆呼叫、單筆失敗不影響其他筆）已完成；待人工測試實際匯入
- [x] 三語言的題目數量、內容可以完全不同，系統不會因為某語言題數少或內容不對應而擋下操作或跳出錯誤
      → 三語言題庫在資料庫層即為互不相關的獨立資料列（無跨語言外鍵關聯），此規則自然成立
- [x] 停用某一題後，該題不會出現在後續的隨機抽題結果中，但既有考試紀錄中的歷史快照不受影響
      → 停用（`is_active=false`）只影響題庫管理列表與（工單 07 待實作的）抽題查詢條件，不刪除資料列，歷史作答快照（工單 07/08）另外存 JSON snapshot，不參照 question_bank 即時狀態

## 補充：後端安全性驗證（2026-07-25）

已用匿名 curl 確認 `question_bank`／`exam_def` 對未登入者完全回空陣列，含正確答案的 `answer_json` 不會透過一般 API 外洩，符合 ADR 0007 的核心要求（新舊兩版 schema 皆已驗證）。

## 補充：架構修訂紀錄（2026-07-25）

原始設計（一題多語言、`question_bank` + `question_translation` 兩張表、答案位置鎖在繁體中文選項順序上）已完整實作並通過建置驗證，但在確認匯入邏輯細節時，使用者明確要求改為三語言完全獨立、無任何對應關係，理由：① 三語言題庫的實際內容與題數本來就不需要對應；② 跨語言共用同一份答案位置，一個環節出錯會牽連所有語言，風險集中。已改為單一 `question_bank` 表（含 `lang_code` 欄位，各列自成一個完整語言版本的題目），並移除 `question_translation` 表與所有跨語言比對邏輯（見 `supabase/migrations/0004_independent_language_question_bank.sql`）。

## 新增：音訊題（聽力題）（2026-07-26 使用者需求）

**需求：** 越南文/印尼文題庫加入音訊題——播放一段情境音效，問「這是什麼情境」，作答方式一樣是單選/複選＋選項；台籍(zh-TW)不考音訊題。

**使用者定案的規則：**
1. 無限重聽，不限制播放次數
2. 音效是情境音效（不是語音對話），vi/id 兩個獨立題目可以共用同一個音檔——這是 Storage 檔案層級的重複使用，資料庫層級 vi/id 還是各自獨立一列（不違反 ADR 0015）
3. 25 題裡固定 5 題音訊＋20 題一般題
4. 音訊題庫還沒建到 5 題以前，維持現狀（25 題全部從一般題庫抽），不會因為音訊題還沒建好就出錯或抽不滿

**實作：**
- `question_bank` 加 `audio_path` 欄位（可為空，見 `supabase/migrations/0014_audio_questions.sql`），開一個非公開的 `question-audio` Storage bucket，平台管理者/系統管理者角色可直接從瀏覽器上傳/預覽（RLS 比照 `question_bank` 本身）
- 題目新增表單（僅 vi/id 顯示）：可以上傳新音檔，或從「已上傳過的音檔」下拉選單挑一個既有檔案重複使用，兩種都能立即預覽播放
- `take-exam` Edge Function：`selectQuestions()` 改成依語言判斷是否要「一般題池20＋音訊題池5」分開抽（各自套用同一套第2次補考排除規則），音訊題池不足5題時完全退回原本邏輯（25題全部從一般題池抽）；開考/續答/結果頁三個地方都會即時簽發限時播放網址（不存進資料庫，每次呼叫都重新簽，避免網址過期）
- 學員考試畫面與結果頁：有音訊的題目上方會出現播放器，`preload="none"` 避免瀏覽器一次把全部音檔都抓下來

**待辦：** Excel 批次匯入題目沒辦法夾帶音檔，音訊題目前只能透過單題新增表單建立。

**部署順序（重要）：** 必須先在 SQL Editor 執行 `0014_audio_questions.sql`，再重新部署 `take-exam` Edge Function——新版函式的抽題查詢會讀取 `audio_path` 欄位，欄位不存在的話所有學員（不只考音訊題的vi/id）都會沒辦法開始測驗。
