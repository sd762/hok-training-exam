# 08 — 學員測驗前端流程（不含監考）

**What to build:** 學員登入後看到自己目前受訓階段的應考提醒，可以開始測驗、依序作答25題（不論題型是單選或複選）、提交後看到分數與及格/不及格結果，以及重考次數/鎖定狀態的清楚顯示。多語言介面（繁中/越南文/印尼文）涵蓋整個作答流程與訊息文字。此工單先不包含鏡頭監考（見工單09）。

**Blocked by:** 07

**Status:** ready-for-agent

- [x] 學員登入後首頁明顯顯示「目前應考測驗」提醒（若有應考義務）
      → **使用者實測通過**：學員登入後看到應考提醒與開始測驗按鈕
- [x] 學員可以開始測驗、看到25題依序作答（含單選/複選題型），選項順序是打亂後的顯示順序
      → **使用者實測通過**：完整作答一次測驗，正常送出
- [x] 提交後立即看到分數、及格與否，以及若不及格時的剩餘次數/鎖定資訊
      → **使用者實測通過及格路徑**（分數顯示、狀態轉為「待核對」）；不及格時的重考次數/鎖定提示文字已實作但尚未實測（見下方）
- [ ] 學員切換到越南文/印尼文語言別後，整個作答流程都顯示對應語言
      → 尚未有越南文/印尼文學員帳號實測，字典內容是初版翻譯，待審閱
- [x] 作答到一半重新整理頁面或關閉瀏覽器再重新登入，可以續答同一次未完成的測驗
      → Edge Function 端邏輯已實作（`start` 動作先查有無 `in_progress` 作答），程式碼檢視合理，未刻意重現「中途關閉再回來」情境實測

## 實測紀錄（2026-07-25）

使用者用學員帳號實際考了一次測驗並**及格**，過程中發現並修正 3 個真實 UX 問題（送出後畫面沒有捲回頂端、返回按鈕位置不順手、不及格時缺乏重考次數提示），已全部修正並重新部署。

及格後該次作答狀態正確轉為 `pending_review`（待核對），符合 ADR 0006——**目前卡在這裡**：需要工單 10（審查流程）做出來，平台管理者才能審查確認，該學員也才能繼續下一階段的測驗。這是很好的真實驗證，但也代表工單 08 剩餘的「不及格重考提示」「多語言」「續答」三項，需要等有新的測試情境（新學員帳號、或工單 10 讓現有這筆作答有個結果）才能繼續測。
