# 10 — 及格審查流程（平台管理者）

**What to build:** 學員及格後，作答狀態進入「待核對」，通知平台管理者。平台管理者可以在一個審查佇列裡看到所有待核對的及格作答，點開查看監考證據（快照、疑似違規事件），確認「核對無誤」（狀態變「已確認通過」，正式納入及格紀錄，對應監考快照可清除）或標記「存疑保留」（保留證據待進一步調查）。學員在「待核對」或「存疑保留」狀態下不能推進到下一受訓階段，也不會誤觸發下一階段的到期通知。「存疑保留」最終被判定不合格時，視為作廢重新計算，不追溯扣考試機會。

**Blocked by:** 09

**Status:** ready-for-agent

      → **使用者實測通過**：T9999 的待核對紀錄正確顯示，監考快照可查看

      → **使用者實測通過**：確認無誤後該筆從審查佇列消失；`advanceStage` 已寫入 `staff_detail.current_stage`，待下次該學員登入時確認能看到下一階段的應考提醒
- [x] 平台管理者標記「存疑保留」後，狀態變為「存疑保留」，監考快照與紀錄不會被清除，該學員無法推進到下一階段

- [~] 機構管理者登入後可以看到自己機構學員的「待核對」/「已確認通過」/「存疑保留」狀態顯示，但沒有任何操作核對的按鈕或權限
      → RLS 已支援（`attempt_read_own_institution` 政策），但**還沒有機構管理者專屬的畫面**可以看到這些狀態——目前只有平台管理者/系統管理者可見的審查頁。機構管理者的檢視畫面留給工單 12（報表）一併處理
- [ ] 學員停留在「待核對」或「存疑保留」狀態期間，即使剛好到了下一里程碑的通知窗口，也不會誤發下一階段的到期通知
      → 判定邏輯已在工單07的 `resolveAssignment` 實作（卡在 pending_review/flagged 時擋下），但實際的到期通知寄送機制是工單 11，目前無法端對端測試這條規則
