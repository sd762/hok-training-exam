# 11 — 到期通知 + 保活排程

**What to build:** 一支負責「到期通知檢查」的 Supabase Edge Function：找出即將到達受訓里程碑（前3天進入通知窗口）且尚未通知過的學員，寄 email 給該學員所屬機構的機構管理者（收件地址取自機構管理者帳號上的聯絡 email 欄位）。同一學員同一階段只通知一次（去重）。搭配一個每天執行1次的 GitHub Actions 排程工作呼叫這支函式——這個呼叫本身同時達成「Supabase 專案保活」的目的（避免免費專案連續7天無活動被自動暫停）。後台需有 SMTP 寄信設定介面與通知紀錄查詢。

      → 「通知設定」頁面（SMTP表單＋「立即檢查一次」按鈕）已完成上線，但 SMTP 欄位還是空的——卡在 Resend 網域驗證的 DNS 紀錄（見下方）

## 現況總結（2026-07-26）

程式碼、部署、排程都已經在正常運作，**唯一卡住的是 SMTP 設定**，而 SMTP 卡在你同事幫忙在 HiNet 幫 Resend 網域加 DNS 驗證紀錄這件事。等 DNS 驗證通過、拿到 Resend 的 SMTP 帳密後：
1. 到「通知設定」頁填入 SMTP 資訊、按「儲存設定」
2. 按「立即檢查一次」手動測試，確認會收到信、通知紀錄正確寫入

就可以把上面剩下的三項打勾，整個工單完成。
