# 11 — 到期通知 + 保活排程

**What to build:** 一支負責「到期通知檢查」的 Supabase Edge Function：找出即將到達受訓里程碑（前3天進入通知窗口）且尚未通知過的學員，寄 email 給該學員所屬機構的機構管理者（收件地址取自機構管理者帳號上的聯絡 email 欄位）。同一學員同一階段只通知一次（去重）。搭配一個每天執行1次的 GitHub Actions 排程工作呼叫這支函式——這個呼叫本身同時達成「Supabase 專案保活」的目的（避免免費專案連續7天無活動被自動暫停）。後台需有 SMTP 寄信設定介面與通知紀錄查詢。

**Blocked by:** 05

**Status:** ready-for-agent

- [ ] 平台管理者可以在後台填寫 SMTP 寄信設定（主機/連接埠/帳號/密碼/寄件人/TLS），並可手動觸發一次通知檢查作為測試
- [ ] 對一位到職日剛好落在「3天後達成里程碑」的測試學員執行檢查，其所屬機構的機構管理者確實收到通知信
- [ ] 同一學員同一階段重複執行檢查不會重複寄信（去重機制生效）
- [ ] GitHub Actions 排程工作每天執行1次，成功呼叫 Edge Function 並記錄執行結果
- [ ] 未設定 SMTP 時，檢查仍會記錄「待通知」名單（狀態標示未寄出）而不是整批失敗中斷
- [ ] 平台管理者可以在後台查詢通知紀錄（寄給誰、什麼時候、狀態）
