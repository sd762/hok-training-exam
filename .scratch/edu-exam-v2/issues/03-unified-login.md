# 03 — 統一登入與帳號代碼機制

**What to build:** 所有角色（學員/機構管理者/平台管理者/系統管理者/管理者）都用「帳號代碼」登入，不碰 email。建立帳號時，程式自動把帳號代碼轉換成 Supabase Auth 要求的內部虛構 email 格式，使用者全程只看到/輸入帳號代碼本身。機構管理者額外多一個「真實聯絡 email」欄位，純粹作為之後通知信的收件地址，與登入身分脫鉤。登入後畫面依角色顯示對應的導覽（先做出最小可用的「登入成功、顯示角色與姓名」畫面即可，各角色的實際功能頁面留給後續工單）。

**Blocked by:** 01, 02

**Status:** ready-for-agent

- [ ] 用種子測試帳號（至少涵蓋系統管理者、平台管理者、學員三種角色）可以用帳號代碼成功登入
- [ ] 登入畫面/建立帳號流程全程不需要輸入或顯示任何 email 格式的文字（機構管理者的聯絡 email 欄位除外，且該欄位清楚標示為「通知用信箱」而非登入帳號）
- [ ] 登入後畫面顯示目前登入者的角色與姓名，證明角色資訊有正確從資料庫讀出
- [ ] 密碼重設走「管理者手動重設」流程，而非 Supabase 內建的寄信重設連結（因為內部虛構信箱收不到信）
- [ ] 嘗試用錯誤的帳號代碼或密碼登入會得到清楚的錯誤訊息，不會洩漏「帳號代碼是否存在」這類可被用來枚舉帳號的資訊
