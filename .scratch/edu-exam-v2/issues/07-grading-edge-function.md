# 07 — 出題與評分 Edge Function（抽題輪替 + 答案鎖定）

**What to build:** 一支 Supabase Edge Function，負責出題快照（只含題目與選項，絕不含正確答案）與評分（比對正解、計算分數、寫回資料庫）。實作同一鎖定循環（3次/輪）內的抽題輪替規則：第1次全題庫隨機抽25題、第2次從扣除第1次抽過的題目後剩餘題目中抽25題、第3次重新全題庫隨機抽25題。題目顯示順序與選項順序各自獨立打亂，正確答案位置鎖定在資料庫的原始選項順序上，透過每次作答產生的對照表換算顯示位置與原始位置。

同時實作「應考哪個階段」的判定邏輯（已合格階段 + 到職日 → 下一個該考的階段，見 `resolveAssignment`），供工單 08 的首頁提醒與開考流程使用。

**Blocked by:** 05, 06

**Status:** ready-for-agent

## 已知缺口，留給工單 10 處理

`attempt_status` 目前只有 `in_progress / failed / pending_review / confirmed_passed / flagged` 五種狀態。ADR 0006 規定「存疑保留最終判定不合格時，不追溯扣考試機會、視為作廢重新計算」——但目前 `getCycleStatus` 的連續失敗次數計算只認得 `failed` 狀態，如果工單 10 把 `flagged` 的作答最終改成 `failed`，會被誤算進鎖定循環，違反 ADR 0006 的規則。工單 10 需要新增一個獨立的狀態（例如 `voided`）來表示「存疑保留後被判定不合格、但不計入考試機會」，並確認 `getCycleStatus` 的查詢邏輯有正確排除它。
