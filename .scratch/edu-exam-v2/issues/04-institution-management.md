# 04 — 機構管理 CRUD

**What to build:** 平台管理者（與系統管理者）登入後可以在後台維護機構清單：新增機構類別、在類別底下新增/編輯/停用機構名稱，取代舊系統寫死在程式碼裡的機構常數。這張機構表是後續學員資料、機構管理者帳號要參照的基礎資料，需先做好。

**Blocked by:** 03

**Status:** ready-for-agent

- [~] 平台管理者可以新增一個機構類別（如「養護機構」）與其底下的機構名稱（如「清安」）
      → UI 已完成、建置通過；實際點擊流程待人工測試確認
- [~] 平台管理者可以編輯既有機構名稱、停用某個機構（停用後不會出現在後續「指派學員機構」的下拉選單，但既有指向該機構的歷史資料仍正常顯示，不會消失或報錯）
      → 更名/停用 UI 已完成；「停用後不出現在指派選單」要到工單 05（學員管理）才有實際下拉選單可驗證
- [x] 機構管理者、管理者、學員角色登入後看不到機構管理的操作介面（RLS 與前端權限雙重確認：純看 API 也拿不到寫入權限）
      → 前端：導覽列項目依 `canWrite(role)` 過濾；後端：已用匿名 curl 實測寫入被 RLS 擋下（42501 + HTTP 401）
- [x] 機構清單的讀取（例如給後續學員指派學員機構用的下拉選單）對所有已登入角色開放，但只有平台管理者/系統管理者能寫入
      → RLS 政策 `institution_read`／`institution_write` 已在工單 02 建立並沿用

## 資料修正（2026-07-26，使用者發現）

舊資料匯入時機構的 `category_id` 指錯類別——「1館/2館/3館」沒有掛在法人館底下、「清X」系列沒有掛在養護機構底下。用 `supabase/migrations/0013_fix_institution_categories.sql`（UPDATE 依機構名稱重新指定類別，非 schema 變更）修正，使用者已在 SQL Editor 執行。
