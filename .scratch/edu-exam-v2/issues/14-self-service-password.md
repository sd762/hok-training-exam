# 14 — 使用者自行修改密碼（2026-07-26 記錄，暫緩實作）

**What to build:** 讓所有角色（學員、機構管理者、平台管理者、系統管理者、管理者）登入後可以自己修改密碼，不用每次都要請管理者用「重設密碼」按鈕恢復成預設值 000000。

**背景：** 寫使用說明頁（工單13）時發現的既有缺口——目前系統唯一的密碼異動方式是管理者手動重設回固定的預設密碼，沒有使用者自行修改的入口。使用者確認這個功能要做，但**先開工單記錄，暫緩實作，等網站其他部分完整後再回頭做**。

**Blocked by:** 03（帳號登入機制）

**Status:** 暫緩（deferred）——不要在沒有使用者明確指示的情況下開始實作

## 待確認的細節（等真的要做的時候再跟使用者確認）

- 修改密碼的入口放哪裡：獨立頁面，還是每個角色現有畫面裡加一個「修改密碼」選單/按鈕（例如導覽列的使用者選單）
- 是否要求輸入舊密碼才能改新密碼（一般常見做法，但這裡帳號代碼登入沒有 email 驗證機制可以搭配，要考慮忘記密碼時的復原路徑會不會因此變複雜）
- 密碼強度規則要不要限制（目前預設密碼 000000 本身就很弱，如果要加強度規則，連帶要考慮新建帳號/管理者重設後的預設密碼是否也要跟著調整）
- 這個改動走 Supabase Auth 內建的 `updateUser({ password })`（前端可直接呼叫，不需要經過 `admin-users` Edge Function，因為使用者改的是自己的密碼，不需要 service_role 權限）
